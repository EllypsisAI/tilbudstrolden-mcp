## [tool-design-methodology] Drift afsløret via user-POV walkthrough; metodologi-decision landed; alignment + roadmap synced

**Skete:**

- User bad om en user-POV gennemgang fra discovery til uge 3, grounded i eksisterende artefakter, for at validere at jeg ikke var biased mod traditionel SaaS. Walkthrough afdækkede to konkrete drift-punkter:
  - **Image handling** beskrevet som server-side vision pipeline (View base64-encoder → backend kalder vision API). User korrigerede: host-agentens native multimodal + en skill der bærer protokollen er det rigtige design. Server-side vision duplikerer kapabilitet vi får gratis og introducerer latency.
  - **Suggest_meals** beskrevet som server-deterministisk pipeline ("ét tool-kald returnerer svaret"). User påpegede at det er én af tre gyldige modeller — agent-driven, server-beriget, eller server-deterministisk — og at valget skal ræsonneres pr tool, ikke globalt.
- Indsigt fra user: "hybrid" er ikke en strategi — det er den emergente form af systemet når hvert tool er designet via dual POV (operating agent + end user). Per-tool POV-walkthrough vælger arketype; vi antager ikke en global default.
- `decisions/tool-design-methodology.md` skrevet (status: proposed → accepted samme session). Komplementerer `three-layer-tool-architecture.md` (visibility-taksonomi) ved at adressere et separat spørgsmål: hvor bor reasoning pr tool.
- Cascading updates til artefakter:

  - `alignment.md` §"Intelligence-laget" — ny subsektion "Hvor reasoning bor pr tool" der eksplicit retracter det implicitte server-deterministiske read af tabel-eksemplerne. Også justering af paragraffen om "serveren orkestrerer internt" → "leverer data, compounding og orkestrering hvor det giver mening — men hvor reasoning bor afgøres pr tool".
  - `alignment.md` §"Åbne spørgsmål" #3 — lukket. Image-recognition workaround er moot for meal-log-pathen.
